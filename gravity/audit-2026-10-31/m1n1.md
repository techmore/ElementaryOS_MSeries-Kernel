## 1. Does Aurora m1n1 `aurora-wip` support J773g?

**SoC (T8132) support: yes, and it covers the mini. Board support: J713 (M4 Air) only**, apart from our c7fdbe7.

SoC-wide features that already work for J773g (no board gate):
| Area | Where | Notes |
|---|---|---|
| CPU/chickens, SMP, MCC, PCIe regs, DART/DAPF (`dapf_init_fdt`) | chickens.c, smp.c, mcc.c, pcie.c, dapf.c | generic `chip_id == T8132` |
| Display | display.c:767 | T8132 always **preserves the inherited iBoot framebuffer** and does no DCP/DART work. So `NO_DISPLAY` is not needed. |
| NVMe in m1n1 | nvme.c:396-481 | `NVME_T8132`; admits the 0x30000 BAR only for `nvmmu 0x485cc0000 / nvme 0x4c5cc0000`. **J773g ADT matches**: ans reg[3] 0x2_85cc0000 and reg[9] 0x2_c5cc0000, +0x2_0000_0000 = those values. A running ANS on T8132 is adopted. |
| ATC PHY tunables | kboot_atc.c | Has an alias quirk for the J773g `tunable_ATC0AXI2AF`. The T8132 USB3 calibration copy is gated to j713 (line 874). |
| Firmware 26.6.2 | firmware.c:212 | `V26_6_2` is known (Gravity's b1c528d has the same line). |
| PMU panic counter, chainload heap handling | pmu_counter.c, chainload.c | Aurora has its own, more thorough versions of Gravity's 7243b81 and 093767c. |

Board-specific gates (all `apple,j713`, except one marked otherwise):
| Gate | Location | Effect on J773g today |
|---|---|---|
| retained m1n1 heap / firmware buffers | kboot.c:6849 `kboot_prepare_dt` | **skipped**: ANS buffers aren't retained |
| chainload high-water reservation + `dt_reserve_bootloader_handoff` | kboot.c:6924 | **skipped** |
| `dt_set_ans_nvme(false)` + `dt_set_t8132_lifecycle` (SPMI/PMU) | kboot.c:6994 | **skipped**: no ANS/NVMe/SART resources go into the DT, so there is **no storage** |
| `nvme_init()` before handing off to the payload (U-Boot or kernel) | payload.c:410 | **skipped**: the ANS session isn't prepared or kept for U-Boot/Linux |
| DCP firmware-mapping handoff `dt_set_j713_dcp_handoff` | kboot.c:5159/5247 | bails for a non-J713 board, prints "refused; keeping the boot framebuffer" and returns 0 (harmless) |
| AOP DAPF handoff | kboot.c:5806 | returns 0 (AOP left alone) |
| PCIe failure → disable instead of abort | kboot.c:7088 | on J773g a PCIe prepare/handoff failure is **fatal** (-1); on J713 it only disables PCIe |
| GPU G16 resource publish | kboot_gpu_m4.c:65 | **j713 or j773g** (our c7fdbe7) |
| PMP | kboot.c:5431 `dt_set_pmp` | generic. If the DT has a `pmp` node it is forced to `status=okay` |
| USB3 ATC calibration | kboot_atc.c:874 | j713 only. The mini gets the USB2 fallback |

Checks of the ADT against the hard-coded J713 constants, which matter because these paths would now run on the mini:
- ANS: `nvme-secure-bar` is present. reg[0]/[3]/[9] and `sart-ans` are present, so `dt_set_ans_nvme()` preconditions hold.
- GPU (`publish_gpu_m4`): sgx reg 0x3_0000_0000/0x4000000, gfx-asc reg 0x3_0260_0000/0x88000, gfx-asc IRQs [994,993,996,995], segment-names `__TEXT;__DATA`, seg0 iova 0xfffffc0000000000 with flag 1 and phys==remap. **All match the J713 constants**, so c7fdbe7's claim holds for this ADT.

## 2. GravityLinux/bootloader compared with Aurora m1n1

Gravity is an m1n1 fork. Its T8132 code has no board gates; everything is SoC-wide, which is why it works on the mini. Gravity-only commits after the fork point ff7489ca:

| Gravity commit | What | Aurora status |
|---|---|---|
| b1c528d firmware 26.6.2 | version table | **present** |
| 47d97ba/f64760b DCP compat 26.6→26.6.2 | DCP compat version | not needed (Aurora has no T8132 DCP driver path) |
| 56c8d21 nvme: support T8132 (Yureka) | m1n1 NVMe | **present and extended** (adoption, split BAR) |
| 61d8910/38dbc02 sio: 26.6.2 firmware-param rules | SIO fwdata table (`copy_rules_26_6_2`, PARAM 0x2a, new blob sizes) | **missing**. Aurora sio.c has only `copy_rules` and `copy_rules_v10`. This only matters if the kernel DT enables `sio` (DP/HDMI audio, ADMA); `dt_setup_sio` skips it on failure. Not boot-critical. |
| b0748b7/20d58ec GPU: `dt_set_gpu_t8132` | reserves 5 regions and sets status okay. Copies all ADT sgx props as `apple,sgx-*`, chip-revision, firmware build, and **derives the `apple,m4-*` perf/voltage tables from the ADT** (11 voltage groups, hard-coded power calib, 37237 mW, core mask 0x3ff) | **Different contract.** Aurora's `publish_gpu_m4` reserves 6 regions plus `apple,firmware-segment-vas/flags` and `g16-handoff-version`, and doesn't start the GPU. Use Aurora's, because our kernel is Aurora's. Aurora publishes no perf tables, so the J773g kernel DT must carry its own (the ADT has 16 perf states, base pstate 3). |
| e8593fe/64af2e1 display: t8132 uses the t8112 DCP reserved-region table plus dcpext and VRAM reservation | needed for Gravity's native DCP driver | Aurora: J713-only DCP handoff. Not needed for framebuffer boot (keep `dcp` disabled in the DT). |
| 12b4b5f/68de116 DAPF: skip DAPF init on T8132 (SError hack) | | Aurora replaced this with `dapf_init_fdt` (only requested consumers; genuine banks other than the AOP are refused) |
| e3a80bf/b9a3637 ATC tunables | | **present** (Aurora is more complete) |
| 950e6b7 NO_DISPLAY Makefile option | | absent in Aurora's Makefile, and **unneeded** (see §1) |
| 3c5b962 fb: map the full VRAM reservation Normal-NC | | Aurora maps `fb_map_size` (fb.c:479). Probably equivalent; check if framebuffer scrolling faults. |
| 093767c chainload heap / 7243b81 PMU panic counter | | present in Aurora in its own form |
| 467c327 proxyclient chainload raw default, artwork/USB strings, licence | | irrelevant |

What Gravity does **not** do: transfer ANS/SART resources into the FDT. Gravity's kernel DT hard-codes a 2-region NVMe node and its driver starts ANS itself. That's why WIP5's T8132 driver (3 regions, separate NVMMU) can't reuse Gravity's DT and needs the Aurora loader handoff.

Gravity's installer (GravityLinux/installer `src/osinstall.py`) builds stage 1 with appended vars `chosen.gravity,efi-system-partition=<uuid>` and `chainload=<esp-uuid>;<next_object>`, padded to 64 KiB "for T8132 registration". Aurora U-Boot reads `asahi,efi-system-partition`. With only the Gravity property it falls back to "the ESP that holds the EFI boot loader" (u-boot 172ce2b), which can be the wrong ESP on a disk with two ESPs.

## 4. Minimal plan

### 4a. Storage + framebuffer (no GPU)
m1n1 (on b6b4592 + c7fdbe7):
1. **0005 (rebased)**: J773g ANS admission via the DT `ans` alias. It retains the heap, reserves the bootloader handoff and runs `dt_set_ans_nvme(false)`. It intentionally does not run `dt_set_t8132_lifecycle` (J713 SPMI/PMU).
2. **0019**: `nvme_init()` before the payload, keep ANS running for Linux/U-Boot, and fail cleanly if there is no live session.
3. Optional: make the PCIe-failure path at kboot.c:7088 non-fatal for j773g as well (copy the j713 behaviour). Otherwise an Ethernet/Wi-Fi PCIe prepare failure aborts the whole boot.
4. Skip 0006, 0010, 0014 and 0018 unless the DT needs them (see §3).

Kernel DT requirements (not m1n1, but the loader contract depends on them): `ans` alias plus ANS/SART/NVMe nodes in the order `nvme, nvmmu, ans` (wip5 0003/0004, and 0002 for the explicit flush). `apple,t8132-nvme-ans2` must stay compatible so Aurora U-Boot binds. Also keep `dcp`, `gpu`, `pmp`, `sio` and `aop` disabled or absent. The framebuffer is iBoot's simple-framebuffer, so HDMI must be connected at power-on.

U-Boot: stock aurora-silicon/u-boot `aurora-wip` (`apple_m1_defconfig`), with **no** per-kernel DTB import. GRUB/BLS entries for our kernel must have **no `devicetree` line**. Only if per-kernel DTBs are wanted: rebase 0007 and 0009 onto 01f255b.

Stage 2 = Aurora m1n1 (`RELEASE=1 CHAINLOADING=1 ESP_STAGE2=1`) + our `t8132-j773g.dtb` + gzip `u-boot-nodtb.bin`, plus appended var `chosen.asahi,efi-system-partition=<new ESP uuid>`.

### 4b. GPU handoff (on top of 4a)
1. m1n1: c7fdbe7 (already there; ADT constants verified). Optionally restore 0010's DT opt-in (`apple,j773g-gpu-handoff-draft`) so a DT without it falls back to a disabled GPU.
2. Kernel DT: `gpu` node `apple,agx-t8132` plus the 6 reserved-memory nodes `uat-ttbs`, `uat-pagetables`, `uat-handoff`, `uat-shared-l2`, `gpu-fw-text`, `gpu-fw-data`. If any is missing, `publish_gpu_m4` fails and the GPU is disabled (safe). It also needs J773g-specific perf/power tables, because Aurora m1n1 doesn't derive them; Gravity's `dt_set_gpu_t8132_perf` shows how to derive them from the ADT.
3. PMP: keep `pmp` out of the DT, or apply 0014 (inspection-only). The mini's PMP power table is unqualified.
4. U-Boot: nothing on the raw-DT path. Per-kernel DTB import would need 0012 re-done from scratch (it doesn't apply anywhere).
5. Native DCP/display is not required for GPU render plus simpledrm. A native display would need a J773g port of `dt_set_j713_dcp_handoff` (and Gravity's e8593fe-style reservations).

### 4c. Installing alongside Gravity without breaking it
- Gravity's stage 1 lives in Gravity's stub boot policy and chainloads a fixed `<gravity ESP>;<next_object>`. **Don't touch Gravity's ESP `m1n1/boot.bin` or its stub.** A stub has only one stage 1, so a second stage 2 needs a second stage 1, i.e. a second stub.
- Recommended: create a **second stub plus its own ESP**. Either use the Gravity installer's UEFI-only flow (it supports j773gap) or build an Aurora stage 1 (`CHAINLOADING=1`, stage1_config with the target and new ESP UUID, padded to 64 KiB) and register it from 1TR with `kmutil configure-boot`. Then put the Aurora stage 2 (§4a) on the **new** ESP, with its own GRUB/UKI pointing at our kernel.
- Rescue: hold the power button → Startup Options → choose the Gravity volume (unchanged) or macOS/1TR. The Gravity BLS entry and ESP stay unmodified.
- Caveats:
  - Untested: a Gravity stage 1 chaining into an Aurora stage 2. Gravity dropped the M4 protected-range check in chainload; Aurora stage 2 reserves the high-water interval from `top_of_kernel_data`. An Aurora stage 1 avoids that combination.
  - If stage 1 can't load its target it drops to the m1n1 proxy, not back to Gravity. That's recoverable via the power-button picker.
  - Not viable: adding our kernel as a GRUB entry under Gravity's stage 2. Gravity's m1n1 applies a different DT contract (2-region NVMe, `apple,sgx-*`/`m4-*` GPU props, no ANS transfer), and a GRUB `devicetree` DTB gets no runtime fixups.
- Alternative without U-Boot/GRUB (rescue/diagnostic): Aurora stage 2 with `boot=` (boot_storage_load) loading Image, DTB and initramfs from the new ESP. This needs 0005 (+0019 for an inline payload), as the wip5 rescue drafts assume.

## Open risks
- None of the m1n1/U-Boot changes have been built here or run on the mini.
- `dt_set_t8132_lifecycle` (SPMI/PMU resources) is J713-only. The mini's kernel DT must not depend on it, or a J773g port is needed.
- The SIO 26.6.2 table is missing in Aurora, which affects HDMI/DP audio only.
- Aurora's T8132 PCIe failure on non-J713 boards is fatal (§4a step 3).
