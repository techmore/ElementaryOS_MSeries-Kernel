# J773g H16 Neural Engine offline build — 2026-10-30

The experimental H16 bring-up module from
[omarchy-ane](https://github.com/joshuaswarren/omarchy-ane/tree/ea8a814b70445e6c36e1ee857c4d6e147a268274/ane/h16)
was inspected at commit `ea8a814b70445e6c36e1ee857c4d6e147a268274` and
built against the existing Aurora graphics candidate, release
`7.2.11-elementary-m4-graphics-draft`. Its `W=1` external-module build
completed without warnings. This is a source/build compatibility result,
not an M4 device, firmware, inference, boot or recovery result. No module,
device-tree overlay or firmware was installed, loaded or exercised on hardware.

The author describes H16 as untested bring-up, without a DRM device or
inference. `stage=dt` is intended to parse device-tree information without
MMIO in the module; the default `stage=status` powers domains and reads
registers. The supplied overlay also enables DART nodes, so the module's
`stage=dt` property alone does not make applying that overlay hardware-silent.
The later firmware boot stage is experimental, and live firmware preload,
DART/DAPF and power-domain ownership remain unresolved. The currently running
Gravity system has no `/dev/accel` directory. The candidate's
`CONFIG_DRM_ACCEL_ANE=m` does not itself establish T8132 support.

## Candidate device-tree mismatch

The author's `t8132-ane-experimental.dts` fragment 0 targets
`/soc/interrupt-controller@381180000`; the recorded graphics rescue DTB
(SHA-256 `abff43e472901a55798b0c3ad833574d13c6fc52ea07a7cf7499180ba440cbc9`)
instead contains `/soc/interrupt-controller@381000000`, compatible
`apple,t8132-aic3`, with three interrupt cells. Its other referenced
power-controller nodes at `570`, `c000`, `c008`, `c010` and `c018` are
present. Therefore the overlay's original AIC target cannot resolve against
this exact candidate as written. No adjusted overlay has been applied to the live system; an
offline path match would still not validate interrupts, hardware ownership,
firmware identity or safe bring-up.

## Offline AIC-path adaptation

`ane-h16-j773g-aic-path-offline-draft.patch` changes only the target path
in the author's overlay against the pinned source. `git apply --check`
passes on that checkout. Using a locally compiled `fdtoverlay` from the
candidate kernel's `scripts/dtc` sources, the original overlay failed on the
recorded graphics rescue DTB with `FDT_ERR_NOTFOUND`; the one-line variant
applied successfully to an isolated copy. Inspection of that output showed
the added ANE and three DART nodes point to the existing AIC phandle with its
three interrupt cells and the expected power-controller phandles. This proves
only device-tree composition; it does not validate the interrupt numbers,
the ranges, power and DART ownership, firmware or hardware behavior.

## Reproduction and local artifacts

The source checkout is `~/.cache/m4-kernel/ane-h16-inspection`. With the
already-prepared candidate build tree and matching clang toolchain:

```sh
git -C ~/.cache/m4-kernel/ane-h16-inspection rev-parse HEAD
make -C ~/.cache/m4-kernel/latest-aurora/graphics/build \
  M="$HOME/.cache/m4-kernel/ane-h16-inspection/ane/h16" CC=clang W=1 -j2 modules
dtc -q -@ -I dts -O dtb -o /tmp/t8132-ane-experimental.dtbo \
  ~/.cache/m4-kernel/ane-h16-inspection/ane/h16/t8132-ane-experimental.dts
```
