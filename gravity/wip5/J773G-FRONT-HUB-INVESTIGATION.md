# J773g front-hub investigation

Read-only observation on the booted Gravity machine on 2026-10-30: `/sys/bus/usb/devices/usb1` and `usb2` resolve to `412280000.usb`, and `lsusb -t` reports their fixed two-port hub at 480 Mbit/s and 10 Gbit/s respectively. `lsusb` identifies the USB2 hub as `05ac:800b` and the USB3 hub as `05ac:800c`. The live device tree's `atcphy2` alias is `/soc/phy@413000000`. This establishes the topology reported by the current running system, not that all traffic is reliable or that a newer kernel is safe.

Gravity's J773g tree describes the front hub as host-only DWC3/ATC2, with fixed USB3 and a lane swap, and sets AP GPIO 101 and 198 high for hub flash output-enable and reset. The newer WIP5/Air ATC integration handles the J713 Type-C route and recognizes fixed USB2 hubs through a graph and hub child, but it does not implement Gravity's `apple,fixed-usb3` and `apple,fixed-lane-swap` properties. Adding the old properties alone would not establish the required SuperSpeed route. Its power sequencing, lane orientation, calibration, GPIO ownership, hub description and two DART windows need a board-specific port and review. The mini front hub is not enabled or included as a claimed working path in the current Aurora draft.

The live Gravity USB DART descriptions use 0x4000-byte register regions, whereas the newer DART v2 handler needs registers beyond that range. The exact hardware DART version and physical aperture ownership still need evidence before enabling the new driver; see `AIR-RADIO-DART-EXPERIMENT.md`. Do not add GPIO hogs or enable the controller merely to make a DT compile.

Rear keyboard investigation: on the booted Gravity system `usb3` resolves to `402280000.usb` and carries the Logitech HID mouse, while `usb4` resolves to `40a280000.usb` and carries the Apple HID keyboard; both are running at 12 Mbit/s through the current kernel. Their live PHY nodes contain firmware-provided tuning properties. The draft m1n1/U-Boot J773g importer currently copies only ANS, ANS-mailbox and SART aliases, not USB resources, tunables or power ownership. The mini draft has rear DWC3, PHY, DART and NUB SPMI nodes disabled; its DART ranges and version remain unresolved. Consequently these observations identify the likely input paths but do not justify enabling them in the new kernel yet. A credible keyboard path requires a validated USB handoff and power/PHY/DART admission on this board; the J713 Type-C proof does not provide it.

The live DT's rear controller 0 uses PMGR domain offset `0xc0` with parents `0x378` (main PMGR) and `0xb0` (NUB PMGR); controller 1 uses `0xc8` with parents `0x428` and `0xb8`. The latest draft describes the same hierarchy. The live NUB SPMI controller is at `0x388908000`, length `0x100`, with PMGR domain `0x68`; the mini-specific draft has the same range and domain, overriding the Air shared tree's larger window. The newer controller falls back to its T8103/gen1 register layout for this compatible pair. These matches identify the intended paths but do not prove safe transitions, DART v2 register coverage or loader preservation.

`j773g-fixed-hub-driver-experiment.patch` is an isolated latest-Aurora ATC driver and binding draft; it does not add or enable a front-hub device-tree node. For a J773g T8132 fixed hub with full SuperSpeed resources and tunables, it attempts the USB3 route on host startup, uses the fixed lane-swap property, and propagates a route failure instead of treating it as a successful USB2 fallback. It rejects the properties on an unsupported machine or incomplete hub setup. The ATC object compiled, the ATC binding passed `dt-doc-validate`, the upstream 13-part ATC host test passed, and a small production-function host harness checked route startup, idempotence, failure propagation and non-hub behavior. These are isolated source/host checks, not hardware qualification.

This is not a complete front USB port: it has no qualified mini front-hub banked PHY resources, tunable import, graph and hub node, GPIO ownership sequence, DART aperture solution, or loader handoff. In particular, `host_active` and common-domain ownership on failed startup and teardown need further lifecycle review. Do not enable the front path based on this draft alone.

`j773g-front-hub-dt-experiment.patch` adds a separate, disabled description for the front DWC3 controller, two DARTs, fixed-hub graph and ATC PHY. It is intended after the driver experiment and is not included in the current build or boot handoff. Controller, USB2 and DART addresses follow the live Gravity tree; the seven-bank SuperSpeed PHY split is inferred from the Air ATC1 layout, not observed or qualified on the mini. The required banked tunables, DART v2 aperture/ownership, GPIO sequencing and loader import remain unresolved. GPIO hogs are deliberately absent. The DT compiled; its front controller, PHY and both DART nodes were read back as `disabled`. The DTB SHA-256 is `32baecce29a13bfc9e097f49433d744b7805454ffe99619e1c99f54289362b7c`. Validation against the full processed schema, limited to the ATC PHY, DWC3 and DART binding IDs, emitted no diagnostics. This is not a full `dtbs_check`; no hardware or boot qualification is claimed.

A source-level lifecycle review found that T8132 failures after common-domain acquisition latch `t8132_failed`; DWC3 cleanup propagates a failed PHY release, retaining ownership rather than resetting an unknown state. A pre-acquisition failure is unwound through the existing USB3 power-off/reset path. The fixed-hub draft now also rejects USB peripheral mode; the generic USB core's SuperSpeed-host request can still fall back to normal host mode. The ATC object and fixed-route host check were rerun successfully. This review does not establish actual hardware teardown or prove every failure path.

Loader source investigation: the staged Aurora m1n1 source `cda8314d2121c0279e4ca811bc6c6293a663e5d0` has a banked T8132 USB3 calibration exporter, but selects it only when the DT root is `apple,j713`. J773g falls through to the older T8122-style list. Its ATC loop visits aliases `atcphy0` onward, so an eventual mini-specific exporter has a defined integration point, but adding J773g to the board gate alone would not prove the mini's ADT property set, bank layout or ownership. Separately, the current J773g U-Boot importer does not carry the USB calibration into the per-kernel DTB. Both handoff stages must be reconciled before the new banked PHY can be enabled.

The DART bases for each USB controller pair are `0x80000` bytes apart (for example `0x402f00000` and `0x402f80000`), so two `0xc000` windows would not overlap each other. The physical size and validity of those larger windows on J773g are still unknown; the live Gravity DT describes `0x4000` windows, which cannot cover the WIP5 v2 fault registers.

`m1n1-j773g-usb3-calibration-experiment.patch` is a separate draft for staged Aurora m1n1 `cda8314d2121c0279e4ca811bc6c6293a663e5d0`. It opts the existing banked T8132 exporter into the J773g fixed front PHY only when the board, SoC, ADT PHY compatible, port 2, fixed-hub property and seven bank names in order all match. On a malformed opted-in description it returns without using the old calibration format; the existing exporter removes incomplete bundles. J713 behavior is unchanged. The m1n1 `kboot_atc.o` object compiled with clang, and the existing J713 calibration fixture plus a host gate test for wrong board, chip, port, ADT, opt-in and bank order passed. The patch has not been linked into the matching loader bundle or tested on J773g; it does not validate physical bank addresses or guarantee the mini ADT supplies all required calibration. The per-kernel U-Boot USB property transfer is still missing, and no loader has been installed.
