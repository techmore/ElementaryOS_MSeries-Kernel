# Air USB SuperSpeed integration experiment

This source-only experiment combines Aurora PR 366 commits `0c5ac13e11b1` (J713 activation and power policy) and `09c50ef2abb5` (J713 SuperSpeed) with conflict resolutions against the Air-forward scratch tree. It is not a standalone patch against stock WIP5. That scratch base already includes the WIP5 display series, J773g SMC/NVMe and disabled rear USB drafts, earlier partial PR 366 replay, and the CPU-frequency thermal-owner and J713 thermal drafts. The full patch was checked for forward application to that base and reverse application to the experiment tree. The scratch base and detailed replay notes are in `/home/sdolbec/.cache/m4-kernel/wip5-source/air-forward/` on the development machine.

The original PR reports 5 Gbit/s qualification on the J713 ATC1 port, not the J773g; it does not qualify the mini's controller addresses, tunables, power ownership or topology. The mini rear nodes remain disabled, requesting USB2 only. Do not install or boot this experiment. It changes shared T8132 power-domain behavior and needs thorough review, a combined kernel build, binding validation and board-specific hardware qualification.

WIP5 already uses `apple,inherited-on` with a distinct display-handoff meaning. The experiment uses the separate provisional property `apple,t8132-inherited-on` for the Air PR's read-only, transition-prohibited handoff, preserving WIP5's existing display behavior. This is a draft binding choice that needs upstream review. It also combines WIP5's `apple,no-auto-pm` rule with the Air T8132 no-auto policy and skips all register access for firmware-owned domains.

Host tests executed from the experimental tree: `pmgr-inherited.py` (5/5), `atc-t8132-usb3.py` (13/13), `dwc3-initial-role.py` (7/7), and `sn201202x-transport.py` (6/6). The ATC harness was adapted to model WIP5's unrelated T8103 fields and assert that its T8103-only branch is not reached in these T8132 tests. These mocked tests do not prove kernel compilation or hardware operation.
